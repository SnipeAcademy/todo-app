# Task 1 Assumptions

## Environment
1. Node.js v22 and npm v10 are available in the environment (confirmed: v22.22.3 / v10.9.8).
2. The working directory `/root/development/todo-app` already exists and contains only `CONVENTIONS.md`, `HERMES.md`, and `tasks/` — no prior scaffold files.
3. Internet access is available for `npm install` to download packages from the registry.
4. `npx` resolves packages from the npm registry (used for `npm create vite@latest` and `npx tailwindcss init -p`).

## Scaffolding strategy
5. Rather than running `npm create vite@latest` interactively (which may prompt for a project name or overwrite confirmation), the scaffold files (`package.json`, `vite.config.ts`, `tsconfig*.json`, `index.html`, `src/main.tsx`, `src/App.tsx`, `src/index.css`, `src/vite-env.d.ts`) will be written directly. This avoids interactive prompts and is equivalent to `--template react-ts`.
6. `package-lock.json` is generated by `npm install` and is therefore not hand-authored; its presence in `allowed_paths` is acknowledged — it will be created by running `npm install`.

## Dependency versions
7. Tailwind CSS **v3** is required (not v4). `tailwindcss@3` is pinned explicitly in the install command.
8. `react-router-dom` is the latest v6.x available from the registry.
9. `date-fns` version is whatever latest stable npm resolves; it is installed but not used in this task (only stubs).
10. `@playwright/test` is the latest stable version. Only the Chromium browser will be installed (`--with-deps chromium`).

## TypeScript
11. TypeScript strict mode is enabled (as required by CONVENTIONS.md and the react-ts Vite template). `tsconfig.json` uses `"strict": true` in `tsconfig.app.json`.
12. All source files will pass `tsc --noEmit` with zero errors.
13. No `any` types are used in hand-authored code.

## Routing
14. `react-router-dom` `<BrowserRouter>` is used (not `HashRouter`) since the verify spec navigates to `/`, `/calendar`, `/completed`, and `/this-route-does-not-exist`.
15. A catch-all `<Route path="*" element={<Navigate to="/" replace />} />` handles unknown routes and redirects to `/`.
16. `<NavLink>` is used for navigation links so that `aria-current="page"` is set automatically on the active link by react-router-dom.

## Layout & styling
17. The `<Layout>` component wraps all routes and renders a `<nav>` element with Tailwind utility classes.
18. Active nav-link styling is handled by react-router-dom's `NavLink` `className` callback (or `isActive` prop), adding a visually distinct class when active.
19. No inline styles are used anywhere; all styling is via Tailwind utility classes only.
20. `src/index.css` contains exactly the three Tailwind directives (`@tailwind base`, `@tailwind components`, `@tailwind utilities`) and nothing else.

## Barrel files
21. `src/components/index.ts`, `src/pages/index.ts`, `src/context/index.ts`, `src/hooks/index.ts`, `src/utils/index.ts`, `src/services/index.ts`, and `src/types/index.ts` are stub barrel files that re-export their contents (or are empty stubs for context/services/hooks/utils/types since no implementation exists yet in this task).

## Playwright
22. `playwright.config.ts` is placed at the repo root (not inside `src/`).
23. `webServer.reuseExistingServer` is `!process.env.CI` — reuses existing server in local dev, always spawns fresh in CI.
24. The verify spec at `tasks/task1/task1-verify.spec.ts` is run with `baseURL: 'http://localhost:5173'`.
25. Only Chromium is installed (`npx playwright install --with-deps chromium`) to minimise install time.

## Out-of-scope items
26. No todo data, business logic, context state, or non-stub components are created — this task is scaffold only.
27. `CONVENTIONS.md` and everything under `tasks/` are not touched.
